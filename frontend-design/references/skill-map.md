# Frontend Design Skill Map

Complete reference for all 29 orchestrated design skills grouped by purpose.

---

## FOUNDATION SKILLS (Always-On Context)

These provide core design philosophy. Load their principles into your thinking for ANY frontend work.

### impeccable
- **What:** Master design system — typography, color (OKLCH), spatial design, motion, interaction, responsive, UX writing. Includes anti-pattern bans (no gradient text, no side-stripe borders). Context gathering protocol via `.impeccable.md`.
- **Invoke:** `/impeccable craft` for full shape-then-build flow. `/impeccable teach` for design context setup.
- **When:** Any new frontend build, component creation, or when design context is needed.

### design-taste-frontend
- **What:** High-agency frontend with 3 tunable dials — DESIGN_VARIANCE (8), MOTION_INTENSITY (6), VISUAL_DENSITY (4). Enforces anti-AI-slop patterns, RSC safety, Tailwind version locking, hardware-accelerated animations, Bento 2.0 paradigm.
- **When:** Building React/Next.js interfaces. Provides the technical execution layer.

### emil-design-eng
- **What:** Emil Kowalski's craft philosophy — animation decision framework (should it animate? what easing? how fast?), spring animations, component building principles, CSS transform mastery, clip-path animations, gesture/drag interactions, performance rules.
- **When:** Any animation or interaction design decision. Review format uses Before/After/Why tables.

### high-end-visual-design
- **What:** $150k agency-level design. Creative Variance Engine with 3 vibe archetypes (Ethereal Glass, Editorial Luxury, Soft Structuralism) and 3 layout archetypes (Asymmetrical Bento, Z-Axis Cascade, Editorial Split). Double-bezel haptic micro-aesthetics.
- **When:** Building premium, Awwwards-tier interfaces.

### full-output-enforcement
- **What:** Prevents code truncation and placeholder patterns. Ensures complete, unabridged output.
- **When:** Any large component or multi-file generation task.

## EVALUATION & REVIEW SKILLS

Use these to assess existing work before making changes.

### audit
- **What:** Technical quality checks across 5 dimensions: accessibility, performance, theming, responsive design, anti-patterns. Scored report with P0-P3 severity.
- **Invoke:** `/audit [area]`
- **When:** User wants accessibility check, performance audit, or technical quality review.

### critique
- **What:** UX-focused evaluation — visual hierarchy, information architecture, emotional resonance, cognitive load. Quantitative scoring with persona-based testing.
- **Invoke:** `/critique [area]`
- **When:** User wants design evaluation, UX review, or qualitative assessment.

### redesign-existing-projects
- **What:** Upgrades existing sites to premium quality. Audits current design, identifies generic AI patterns, applies high-end standards without breaking functionality.
- **When:** User has an existing project that looks generic or dated and wants it upgraded.

## AESTHETIC PRESETS (Style Specializations)

Use these when a specific aesthetic direction matches the project.

### minimalist-ui
- **What:** Clean editorial style — warm monochrome palette, typographic contrast, flat bento grids, muted pastels. No gradients, no heavy shadows.
- **When:** Notion/Linear-inspired interfaces, editorial sites, clean dashboards.

### industrial-brutalist-ui
- **What:** Swiss typography + military terminal aesthetics. Rigid grids, extreme type scale contrast, utilitarian color, analog degradation (CRT scanlines, dot-matrix).
- **When:** Data-heavy dashboards, developer portfolios, editorial sites needing raw mechanical feel.

### stitch-design-taste
- **What:** Semantic design system for Google Stitch. Generates DESIGN.md files enforcing premium standards.
- **When:** Google Stitch projects or when generating semantic design system documentation.
